# Harbor Terminal 1.1.0

کنسول شخصی هاست cPanel، بدون نیاز به SSH؛ افزونه برای Edge، Chrome و Firefox، و یک فایل PHP برای هاست.

## نصب سریع روی Edge ویندوز

1. از [آخرین نسخه](https://github.com/A-Masoumiyan/harbor-terminal/releases/latest) فایل **harbor-terminal-chrome-edge-1.1.0.zip** را دریافت و Extract All کنید.
2. در نوار آدرس Edge بنویسید `edge://extensions`، حالت Developer mode را روشن و Load unpacked را بزنید.
3. پوشه‌ای را انتخاب کنید که **manifest.json** داخل آن است. آیکون Harbor Terminal را از منوی افزونه‌ها روی نوار ابزار نمایش دهید.

راهنمای `INSTALL-FA.txt` داخل بسته هم همین مراحل را توضیح می‌دهد. نسخهٔ آماده با ZIP سورس فرق دارد، اما از این نسخه پوشهٔ اصلی سورس هم برای Edge قابل بارگیری است.

برای Chrome مراحل یکسان و آدرس `chrome://extensions` است. بستهٔ Firefox مخصوص نصب موقت از `about:debugging#/runtime/this-firefox` است؛ نصب دائمی هنوز به امضای Mozilla نیاز دارد. حداقل Chrome/Edge 120 و Firefox 140.

## شروع روی هاست

### اگر ترمینال قبلی دارید

در تنظیمات افزونه «اتصال موجود» را باز کنید، آدرس صفحهٔ `harbor-terminal-شناسه.php` را وارد و «بررسی و افزودن اتصال» را بزنید. رمز و فایل قبلی دست‌نخورده می‌مانند. اتصال نسخه‌های قبل هم خودکار به فهرست چندهاستی منتقل می‌شود.

### برای نصب تازه

1. وارد cPanel شوید، پوشهٔ سایت را در File Manager باز کنید و Upload را بزنید.
2. در همان تب، روی آیکون افزونه بزنید. نشانی Upload خودکار به تنظیمات منتقل می‌شود؛ «تشخیص دامنه و مسیر» را بزنید.
3. مقصد را بررسی، مالکیت هاست را تأیید و نصب را انتخاب کنید. **رمز ساخته‌شده را همان لحظه ذخیره کنید**؛ افزونه رمز را دائمی نگه نمی‌دارد. بعد «بررسی نصب» و «باز کردن ترمینال» را بزنید.

اگر API پنل پاسخ نداد، بخش **نصب دستی ساده** فایل PHP آماده می‌سازد: فایل را دریافت و با File Manager آپلود کنید، سپس «آپلود کردم؛ بررسی و ثبت اتصال» را بزنید. در هر دو روش، هاست باید Linux، PHP 8.1+، HTTPS معتبر، سشن فعال و اجازهٔ اجرای `proc_open` و توابع وابسته داشته باشد.

آزمون ساده: `pwd && whoami && ls -la`

## به‌روزرسانی نصب فعلی

1. در تنظیمات افزونه «بررسی نسخهٔ جدید» را بزنید و بستهٔ مرورگرتان را دریافت کنید.
2. فایل‌های ZIP را در **همان پوشهٔ نصب قبلی** جایگزین کنید و در صفحهٔ افزونه‌ها Reload را بزنید؛ افزونه را حذف نکنید.
3. برای امکانات جدید روی هاست، نشانی تازهٔ Upload همان پوشه را تشخیص دهید و «آماده‌سازی ارتقای ترمینال فعلی» را بزنید. پشتیبان خصوصی را دریافت، تأیید و ارتقا را اعمال کنید. آدرس، رمز و محدودیت IP حفظ می‌شوند.
4. صفحهٔ ترمینال را تازه‌سازی کنید. نسخهٔ افزونه و نسخهٔ هاست در تنظیمات کنار هم قابل بررسی‌اند.

حذف یا جابه‌جایی پوشهٔ نسخهٔ unpacked ممکن است شناسهٔ افزونه و تنظیماتش را عوض کند؛ در آن صورت از «اتصال موجود» استفاده کنید. دریافت بسته از داخل افزونه انجام می‌شود، ولی جایگزینی خودکار افزونهٔ دستی Edge/Chrome محدودیت مرورگر است و انجام نمی‌شود. انتشار فروشگاهی هنوز انجام نشده است.

اگر ارتقا مشکل داشت، در بخش نسخه‌ها پشتیبان قبلی همان ترمینال را انتخاب و بازگردانی کنید؛ اطلاعات ورود فعلی حفظ می‌شوند. برای بازگردانی هم باید همان پوشهٔ cPanel را تشخیص داده باشید. هیچ آپلود یا بازگردانی بعد از قطع پاسخ، خودکار تکرار نمی‌شود. اگر OPcache هاست تغییر فایل را بررسی نمی‌کند، پشتیبانی باید کش PHP را تازه کند.

## امکانات نسخهٔ ۱٫۱٫۰

- چند هاست با نام، رنگ و انتخاب اتصال فعال؛ کلیک آیکون، ترمینال فعال را باز می‌کند. در تب Upload، همان کلیک تنظیمات نصب را باز می‌کند.
- **Shift+Enter برای اجرا**؛ Enter برای خط جدید. Ctrl+Enter هم برای سازگاری باقی مانده است.
- **↑ و ↓ برای تاریخچه** در ابتدا/انتهای خطوط؛ داخل متن چندخطی، حرکت معمول نشانگر حفظ می‌شود. دکمه‌های قبلی/بعدی هم کنار تاریخچه هستند و فرمان نیمه‌نوشته پس از برگشت از تاریخچه بازیابی می‌شود.
- تاریخچهٔ مرورگر با مسیر، زمان و کد پایان؛ جست‌وجو، منتخب‌های پایدار و دریافت تاریخچهٔ هاست. پاک‌کردن تاریخچه، مرورگر و در صورت دسترسی، تاریخچهٔ همین ترمینال روی هاست را پاک می‌کند.
- پیشنهاد فرمان و **Tab برای تکمیل فرمان یا نام فایل در پوشهٔ فعلی**؛ نام‌های دارای فاصله و کوتیشن برای شِل نقل‌قول می‌شوند. Ctrl+K پنل جست‌وجو را باز می‌کند. هیچ پیشنهادی خودکار اجرا نمی‌شود.
- خروجی زندهٔ متن، آمار اجرا، جست‌وجو، کپی و ذخیرهٔ TXT. اعلان موفقیت یا خطا کوچک، قابل‌بستن و بدون جابه‌جایی صفحه است؛ جزئیات در خروجی می‌ماند.
- مرور پوشه‌ها، تغییر مسیر با کلیک، دریافت فایل تا ۱۰ مگابایت و آپلود تا ۵ مگابایت؛ فایل موجود بازنویسی نمی‌شود.
- مشاهده و پایان‌دادن به ورودهای دیگر، محدودیت تلاش ناموفق و قفل موقت پس از پنج تلاش ناموفق.
- بررسی نسخه‌ها و قابلیت‌های هاست، گزارش خطای بدون رمز و بازگردانی نسخهٔ قبلی.
- رمز دلخواه حداقل ۴ کاراکتر و حداکثر ۲۵۶ بایت؛ تغییر موفق، ورودهای قبلی را باطل می‌کند.

## محدودیت‌های هاست

هر اجرا یک شِل تازه با دسترسی کاربر PHP است؛ `cd` بین اجراها حفظ نمی‌شود و باید مسیر فرم را عوض کنید. برنامه‌های تعاملی و ترمینال PTY پشتیبانی نمی‌شوند. اجرای زنده حداکثر حدود ۲۰ ثانیه و خروجی تا ۲۵۶ کیلوبایت است؛ مسیر HTML بدون JavaScript همچنان حدود ۱۰ ثانیه سقف دارد.

بعضی پراکسی‌ها و هاست‌های اشتراکی خروجی را با تأخیر یا یکجا می‌فرستند؛ PHP نمی‌تواند این رفتار را همیشه تغییر دهد. «درخواست توقف» به اجرای شِل ارسال می‌شود، اما توقف همهٔ فرزندان تضمین نمی‌شود. پاسخ هم‌زمان به درخواست توقف به امکان چند درخواست هم‌زمان PHP در هاست وابسته است.

مدیریت نشست‌ها، توقف جداگانه، تاریخچهٔ سمت هاست و محدودیت ورود مشترک به پوشهٔ موقت خصوصی و قابل‌نوشتن نیاز دارند. در نبود آن، وضعیت قابلیت‌ها مشخص می‌شود و محدودیت ورود فقط در سشن همان مرورگر اعمال می‌شود. هیچ دسترسی روت یا SSH ساخته نمی‌شود و محدودیت‌های هاست دور زده نمی‌شوند.

تاریخچه و منتخب‌ها در localStorage همان سایت و شناسهٔ ترمینال ذخیره می‌شوند. تا ۱۰۰ اجرای زنده در پوشهٔ خصوصی موقت هاست نگه داشته می‌شود. فیلد رمز ورود در تاریخچه ذخیره نمی‌شود. جزئیات داده‌ها در [PRIVACY.md](PRIVACY.md).

## ساخت و بررسی

Node.js 22+، Python 3 و PHP 8.1+ لازم است. وابستگی runtime بیرونی وجود ندارد.

```text
node --test tests/*.test.js
python tests/php_integration.py
python tools/build.py
```

بسته‌ها در `dist/` ساخته می‌شوند؛ manifest و ورودی‌های هر بسته بررسی می‌شوند. آزمون‌های HTTP، HTTPS/CSRF، ورود و رمز چهارکاراکتری، فایل‌ها، آپلود/دانلود، نشست‌ها و محدودیت تلاش را پوشش می‌دهند. در لینوکس، خروجی UTF-8، اجرای زنده و درخواست توقف هم‌زمان هم آزموده می‌شوند. آزمون‌های JavaScript مهاجرت چندهاستی، شروع واقعی ماژول تنظیمات، کلیک نوار ابزار، تاریخچه، کلیدها و آماده‌بودن اجزای رابط را بررسی می‌کنند.

با tag مثل `v1.1.0`، workflow پس از آزمون‌ها ZIPها و SHA256SUMS را در Releases قرار می‌دهد. برای نسخهٔ بعد، شماره در package.json، manifestها و قالب PHP باید هماهنگ باشد. آزمون cPanel واقعی و تمام نسخه‌های مرورگر از این آزمون‌ها نتیجه نمی‌شود؛ سازگاری محیط میزبانی باید بررسی شود.
